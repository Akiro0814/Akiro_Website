# 独立评论系统

评论由本站 Express 服务与原生前端组件提供，不再加载 Twikoo、tkserver 或其 SDK。文章、随笔共享后台的实时评论库，提交即展示，隐藏、恢复、回复、删除与点赞无需构建。静态发布及回滚不会覆盖评论。

## 使用

评论区提供昵称、可选邮箱、Markdown、预览、回复、点赞、排序、分页及划词引用。邮箱只用于服务端通知，不公开。昵称可保存在本浏览器，邮箱不保存至浏览器存储。支持 Ctrl/Cmd+Enter 提交。

每条访客评论展示系统、浏览器及可识别版本。识别依据请求 UA 与浏览器主动提供的 Client Hints；无法确定时显示未知。没有足够信息区分 Windows 10/11 时显示 `Windows 10 / 11`，不会猜测为精确版本。这些信息可被客户端修改，只用于展示。原始 UA 不出现在公开接口中。

后台「评论」可搜索、回复、隐藏、恢复和级联删除；隐藏任意祖先后，其下回复也不对访客公开。「评论设置」可开启/关闭评论、设备展示、通知，调整分页、长度和提示文案。设置即时生效，已打开页面可点击刷新（页面可见时也定期刷新）。

基础防刷包含 IP 分桶限流、与 IP 绑定的签名短时挑战、最短填写时间、蜜罐字段及浏览器同源检查。采用服务端 HTML 白名单净化，前端再净化。该轻量机制不等同于旧 Cap 的人机验证；持续遭遇自动化攻击时应在反代或 WAF 加强防护。

## 升级迁移

1. 停止旧后台，保留整个 `data/` 与私密环境配置；不要让两个进程同时写同一目录。
2. 更新依赖、重启后台。首次读取评论时自动解析本地 Loki 元数据与所有分片，先复制旧库到 `data/comment-migration-backup/twikoo/`，再原子创建 `data/comments-store.json`。旧文件不改动。
3. 保留 ID、正文、时间、回复关系、站长标记、隐藏状态和点赞数量；旧点赞身份不迁移，只保留数量。已迁移过的 `comments.json` 不再重新导入，避免复活删除的旧评论。
4. 在后台核对首次迁移数量、评论状态和抽样回复，重新构建发布前台。新库存在后不再从旧库自动补数据，重启不会复活已删除评论。

损坏的新库或旧分片会拒绝写入，不静默当作空数据。远程 HTTP/MongoDB 模式须先从原服务导出，清除相应旧环境变量后，在「评论设置」导入 JSON；本地迁移器不会连接远程数据源。迁移器也支持原有 `TWIKOO_DATA` 自定义目录；迁移完成后可移除该旧环境变量。

后台支持本站导出文件与 Twikoo 评论数组，16MB 以内按 ID 合并；已有同 ID 记录优先，不覆盖审核结果。导出含邮箱等私有字段，不含 SMTP 密码和推送密钥，请勿公开。导入只导入评论，不自动启用文件中的通知或展示设置。

## 通知与备份

本地迁移会保留旧库中的 SMTP、站长邮箱和推送配置，仅在服务器使用。后台「评论设置」可直接编辑站点信息、站长收件邮箱、SMTP 主机/端口/加密/账号/授权码、发件人、Server酱通道与 SendKey。保存立即生效，写入私有 `data/comments-store.json`，无需手动改配置文件或重启。

密码、SendKey 不回显；留空保留原值，勾选明确的清除选项才删除。优先级按字段计算：后台明确保存的配置 > `COMMENTS_*` 环境变量 > 旧库迁移值。未在后台设置的字段可继续通过 `.env.example` 的 `COMMENTS_SMTP_*`、`COMMENTS_BLOGGER_EMAIL`、`COMMENTS_SENDER_*`、`COMMENTS_PUSHOO_*` 提供；改变环境变量后需重启。显式 SMTP 主机优先于预设服务名称，STARTTLS 模式要求服务器完成 TLS 升级。保存配置不会自动发送测试通知。

管理评论列表及 SMTP/站长推送的页面地址统一显示中文路径，原始编码路径保留用于页面匹配。配置站点地址后，通知还包含完整的中文链接；异常百分号转义不会使页面或通知崩溃。

新评论可通知站长，回复可通知原评论邮箱。支持 SMTP 与 Server酱 Turbo（`serverchan`、SCT token）。未配置的通道跳过，旧系统的其他 PushOO 通道、第三方图片上传及外部验证码插件不再加载；评论可使用 Markdown 图片链接。原库备份仍保留旧配置供人工迁移。

通知任务先持久化，失败按指数退避重试，最多 5 次；后台设置页显示待处理数。通知采用尽力投递，服务商接受不等于收件箱或微信实际送达；进程在投递与确认之间退出可能重复投递。通知失败不回滚已成功保存的评论。

停服后备份整个 `data/`；`comments-store.json` 同时包含评论与私密通知设置，不得放入公开静态目录。常规项目备份已包含 data。恢复时保持新库与对应备份一致，原库备份仅供回溯，不要删除新库后期待重新迁移保留后续修改。

## 验证

`npm run verify` 覆盖单元、HTTP、发布隔离、静态检查及构建。`npm run test:comments-ui` 使用虚构内容和临时数据库，验证提交、设备标签、点赞、预览、引用、后台回复与隐藏/恢复、导入导出、权限和手机布局，不发送真实邮件或推送。
